## 전송 및 연결 복구 검증 (2026-11-14)

- 메시지별 전송 중/실패, 동일 키 재전송, 동시에 누른 재전송 잠금. 서버 send_message의 기존 중복 방지 제약을 사용하므로 DB 변경 불필요.
- 실패 전송은 계정별 sessionStorage에 보관. 같은 탭 새로고침에는 유지되며 탭/앱 세션을 완전히 종료한 뒤의 복원은 보장하지 않음. 실패 메시지를 자동 전송하지 않고 재전송 버튼으로 사용자가 결정.
- 온라인/창 복귀/실시간 재구독 및 5초 보완 조회로 마지막 조회 순번 이후를 복구. 페이지 중간 실패 시 성공한 페이지부터 이어서 조회.
- outbox/recover 테스트: 응답 유실, 중복 클릭, 계정 분리, 새로고침, 서버 확인 뒤 늦은 오류, 대화 전환, 205개 누락 메시지의 부분 실패 후 복구.
- 실제 기기 검증: 양쪽 새로고침 → 휴대폰 비행기 모드(Wi-Fi도 끔) → 실패 메시지 생성 → 노트북에서 별도 메시지 전송 → 휴대폰 재연결 → 누락 메시지 자동 도착 확인 → 실패 메시지 재전송 연타 → 상대에 한 건만 저장됐는지 새로고침 후 확인.

## 사진·파일 전송 (2026-11-14)

- 0007_attachments.sql: private chat-files bucket, 최대 10MiB/파일, 20개 준비/시간/사용자. 기존 메시지와 API 유지.
- 업로드 준비 → immutable 오브젝트 업로드 → send_attachment로 메시지 확정. UUID를 재사용하며 메시지 중복 저장과 파일 덮어쓰기를 차단. 미완료 업로드는 재시도를 위해 유지.
- 업로더는 준비 중 파일에 접근 가능, 상대는 메시지 확정 후 접근 가능. 대화 밖 사용자·비로그인 사용자 접근 거절. 차단 후 새 첨부 금지, 기존 첨부 열람 유지.
- JPEG/PNG/GIF/WebP는 바이트 시그니처를 검사해 사진으로 표시. 다른 파일은 octet-stream 다운로드. 비공개 Storage 인증 다운로드로 blob URL을 생성하며 HTML/SVG를 앱 내부에 렌더링하지 않음.
- 파일은 한 번에 1개. 선택한 파일을 전송할 때 입력한 텍스트 초안은 보존. 새로고침 후 업로드가 완료되지 않았다면 원본 파일 재선택 필요.
- attachments-db: 준비/완료 권한, 존재·크기·타입 검증, 중복 전송, 외부 접근 및 수정 차단. attachment-delivery: 업로드 실패, 응답 유실 후 재시도, 파일 미선택 복원.
- 실제 기기 확인: 양쪽 새로고침 → 휴대폰 사진 1장 → 노트북 미리보기·다운로드 → 노트북 PDF 1개 → 휴대폰 다운로드 → 새로고침 후 첨부 유지. 네트워크 끊김 중 재전송 및 10MiB 초과 파일 거절도 확인.
