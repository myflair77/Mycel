# 전화번호 기반 친구 발견 검토
2026-11-13 사용자 질문에 대한 설계 후보. 구현 승인으로 간주하지 않으며 주소록을 읽거나 업로드하지 않음.

## 가능 범위
전화번호를 검증된 인증 서비스의 SMS OTP로 계정에 연결하면 가입자 매칭 가능. 이메일 로그인과 별개의 선택 기능으로 두는 안을 권고.
웹/PWA는 전체 주소록의 지속 자동 동기화를 보장할 수 없다. Android Chrome Contact Picker는 사용자가 직접 고른 연락처만 전달하며 반복 접근은 다시 선택해야 한다. PWA 설치는 네이티브 주소록 권한을 추가하지 않는다.
주소록 동기화가 핵심이면 Android/iOS 네이티브 또는 네이티브 브리지 앱을 별도 검토해야 한다. OS 권한 거절/제한 허용/변경을 처리해야 하고 백그라운드 실시간 동기화를 보장하지 않는다.

## 추천 사용자 흐름
1. 기본 사용자 ID/초대 링크/QR로 친구를 찾는다.
2. 선택적으로 내 번호를 인증하고 '전화번호로 나를 찾기' 공개 범위를 정한다.
3. 지원 기기에서 사용자가 연락처 매칭을 요청하고 사용할 항목과 전송 목적을 확인한다.
4. 인증된 번호를 연결했고 발견을 허용한 사용자만 친구 추천으로 표시한다.
5. 수락 전에는 친구 관계를 생성하지 않는다. 차단 관계는 추천/요청 모두에서 제외한다.

## 서버 설계 쟁점
국가번호 포함 정규화, SMS 발송 비용/재시도 제한, 번호 변경·재할당·탈퇴/연결 해제, 검색 남용 방지.
친구 검색 응답을 계정 존재 여부를 무제한 조회하는 API로 만들지 않는다.
주소록 이름/메모 등 불필요한 정보는 업로드하지 않는다. 일치하지 않는 번호의 장기 보관을 기본으로 삼지 않는다.
단순 SHA 해시만으로 전화번호가 익명화된다고 주장하지 않는다. 조회 가능한 공간이 작아 대입 공격 가능. 보안 설계는 키 관리와 속도 제한을 포함해 별도로 검토한다.
네이티브 전환 여부는 연락처 동기화 우선순위가 정해진 뒤 결정.
