# 개별 대화창 설계

상태: 설계 완료. 기본 화면은 대화 목록과 선택한 대화가 함께 보이는 분할 화면을 유지한다.

## 열기와 창 관리
- 목록 한 번 클릭은 메인 창에서 대화를 선택한다. 각 행의 더보기 메뉴와 데스크톱의 우클릭 메뉴에 '별도 창으로 열기'를 둔다. 키보드 메뉴도 같은 기능을 제공한다.
- 별도 창은 대화 헤더·내용·입력창만 표시한다. 방 ID는 그대로 사용하며 새 방이나 메시지 복사본을 만들지 않는다.
- 계정 ID와 방 ID를 창 식별자로 사용한다. 이미 열린 방은 해당 창을 앞으로 가져온다. BroadcastChannel과 만료되는 창 생존 신호로 여러 메인 창 사이에도 중복 열기를 막고, 지원하지 않으면 storage 이벤트로 보완한다.
- 팝업 차단 시 안내와 사용자가 직접 누르는 새 창 열기 버튼을 제공한다. 태블릿·휴대폰 기본 동작은 기존 화면 전환을 유지한다.

## 동기화와 읽음
- Supabase를 메시지·참여자·권한·읽음 상태의 기준으로 삼는다. 별도 창에서도 동일한 접근 제어, 참여 시점 제한, 전송 재시도와 중복 방지를 사용한다.
- 보이고 포커스된 창에서 최신 메시지가 실제로 보이는 경우에만 읽음 처리한다. 숨겨진 메인 대화나 최소화된 창은 읽음으로 처리하지 않는다. 읽음 위치는 서버에서 단조 증가시킨다.
- 같은 기기의 여러 창은 알림을 메시지 ID별로 중복 방지한다. 어느 창에서든 해당 방을 실제로 읽고 있으면 알림을 억제하고, 읽음 및 배지를 다른 창에도 전달한다.
- 각 창의 작성 중 초안은 창별로 보존해 다른 창의 입력을 덮어쓰지 않는다. 전송 요청 ID는 개별 전송마다 고유하게 생성한다.

## 닫기·계정·창 위치
- 창 닫기는 대화방 나가기·삭제·로그아웃과 구분한다. 메인 창을 닫아도 별도 창의 인증 갱신과 대화는 계속된다. 로그아웃이나 계정 변경은 열린 모든 창에 전달해 이전 계정 내용을 즉시 숨긴다.
- 기기·브라우저·계정·방별 창 크기와 위치를 로컬에 저장한다. 기본 480×760, 최소 목표 360×480으로 시작하며 화면 영역에 맞게 보정한다. 웹 브라우저가 위치·크기 제어를 제한할 수 있으므로 보장은 하지 않는다.
- 재시작 시 자동 다중 팝업 대신 '이전 대화창 다시 열기'를 사용자가 선택하게 한다. 다중 모니터가 사라진 경우 현재 화면 안으로 보정한다.

## 검증 기준
동일 방 중복 열기, 팝업 차단, 키보드 조작, 메인/개별 창 닫기, 오프라인 재전송, 여러 창의 읽음과 알림 중복, 역할·차단 변경, 로그아웃, 창 크기 복원 및 모니터 변경을 확인한다. 기존 메시지·첨부·친구 관계는 변경하지 않는다.
