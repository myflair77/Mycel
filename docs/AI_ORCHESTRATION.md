# AI 연결 및 오케스트레이션 — 후속 확장
2026-11-13 사용자 요청 반영. 초기 메신저 MVP 이후 구현하며 현재 연결 기능은 없음.

## 의도
메신저를 사람과 AI의 작업 대화 창구로 사용한다. Dot을 메인 오케스트레이터로 두고 여러 Codex 작업자에게 일을 배분한다. Gemini, JEV 등 다른 AI도 제공 API를 통해 프로그램 운영 업무를 수행할 수 있도록 한다.

## 논리 구조
사람 ↔ 메신저 채팅 ↔ 오케스트레이션 게이트웨이 ↔ Dot
게이트웨이 ↔ Codex 작업자 1..N / 외부 AI 제공자별 어댑터

이 구조는 목표 모델이다. Dot/Codex 제품의 실제 외부 제어 API, 인증, 이벤트 수신 지원 여부를 검증하기 전 직접 연결 가능하다고 단정하지 않는다. 현재 개발 에이전트에서 사용할 수 있는 도구가 배포된 메신저에도 제공된다고 가정하지 않는다. JEV의 정확한 서비스명/공식 API 문서는 구현 전에 확인한다.

## 대화와 실행 분리
- conversations/messages: 사람과 AI가 주고받는 표시 기록.
- agent_connections: 제공자, 기능, 권한 범위, 서버 비밀 저장소 참조.
- tasks/task_runs: 요청자, 담당 오케스트레이터, 상위 작업, 상태, 비용 한도.
- run_events: 순번, 상관 ID, 중복 방지 이벤트 ID, 상태 변경과 진행 보고.
- artifacts: 결과 파일/코드/로그의 접근 권한과 출처.
- approvals/audit_events: 승인 대상 행위·리소스·만료·실행 결과.

상태 초안: queued → running → waiting_for_approval → succeeded/failed/cancelled.
대화 메시지의 삭제/수정으로 실행 기록을 소급 변경하지 않는다.
채팅 전송 성공과 작업 실행 성공은 서로 다른 상태다.

## 양방향 계약
사용자 요청 → 서버 인증/권한 검사 → 작업 저장 → 큐 → 오케스트레이터 배정.
작업자 이벤트 → 서명/발신자 검증 → 중복 제거/순번 기록 → 메시지 알림.
누락된 이벤트는 재연결 커서로 복구한다. 타임아웃/재시도/취소 전파/작업자 중단을 처리한다.
작업마다 workspace와 branch/worktree를 분리하고 동일 파일 동시 변경을 조정한다.

## 운영 경계
API 키는 클라이언트/채팅/일반 DB 평문에 저장하지 않는다.
채팅방 참여와 코드 실행/배포 권한은 별개다. AI마다 허용 도구와 리소스를 제한한다.
비용/토큰/실행시간/동시 작업 수 한도, 비상 중지, 실행 감사 기록을 둔다.
배포·삭제·결제·외부 전송은 해당 행위에 대한 명시적 승인 흐름을 적용한다.
외부 문서/AI 출력은 사용자 명령으로 취급하지 않는다.
운영 작업은 전용 격리 실행 환경과 제한된 서비스 계정을 사용한다.

## 구현 순서 및 검증
1. 메신저의 계정/권한/영속 메시지 MVP 완성.
2. 연결할 제품의 공식 API/SDK·요금·사용 조건·이벤트 수신 방식을 확인.
3. 제공자 하나로 읽기 위주 요청/응답, 취소/실패/재연결 실험.
4. Dot 오케스트레이션과 다중 Codex 배분 실험.
5. Gemini/JEV 어댑터, 운영 업무, 승인·비용 제한 확대.

필수 테스트: 다른 방 작업 열람 거절, 위조 콜백 거절, 중복 이벤트 단일 처리, 승인 전 실행 차단, 취소 전파, 비용 한도 초과 중지, 재접속 기록 복구.
