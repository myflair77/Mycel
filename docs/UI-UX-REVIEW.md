# 메신저 UI·UX 점검 및 개선안

작성: 2026-11-14. 현재 소스, 사용자가 제공한 카카오톡 데스크톱 화면, 실제 사용 피드백을 기준으로 작성했다. 아래 수치와 배치는 우리 제품의 제안이며 카카오톡의 공식 규격이 아니다. 실제 갤럭시 폴드4·태블릿 조작 테스트는 후속 검증으로 구분한다.

## 1. 방향과 우선순위

## 2. 기기별 기본 구조

물리 기기 이름 대신 CSS 뷰포트 폭을 기준으로 한다. 권장 초기 분기: 680px 미만 1열, 680~1099px 목록+대화 2열, 1100px 이상 데스크톱. 이후 실측으로 조정한다. 사용자 강제 모드는 유지하되 좁은 화면에서는 패널을 접어 입력 불가능한 배치를 피한다.

### 휴대폰 / 폴드 접힘

- 목록 화면: 상단 제목 ‘대화’, 검색·새 대화, 목록, 하단 ‘친구 / 대화 / 설정’. 새 요청 수는 친구 탭에 표시한다.
- 대화 진입: 목록·세로 레일·하단 탐색바를 모두 숨긴다. 상단은 ‘뒤로 / 이름 / 검색 / 더보기’. 뒤로 가면 이전 목록 위치를 복원한다.
- 글자 크기 조절은 사용자 요청대로 메인 상단의 − / 100% / +를 유지한다. 대화 안에서는 같은 설정을 더보기에서 접근하게 하는 방안을 제안한다. 이동은 별도 구현 시 합의할 사항이다.
- 입력: + / 입력칸 / 전송의 한 줄을 기본으로, 내용에 따라 4~5줄까지 커진다. 모바일 Enter는 줄바꿈, 전송은 명시적 버튼.
- 첨부 선택 후 작은 미리보기와 취소 버튼. 파일 제한·30일 보관 설명은 첨부 패널에서 보여주고 평상시에는 공간을 줄인다.
- 터치 버튼 목표 44~48 CSS px. 보이는 아이콘은 작아도 터치 영역은 확보한다.
- 안전 영역과 소프트 키보드를 반영한다. 안드로이드 뒤로는 팝업 닫기→검색 종료→목록 복귀 순으로 동작하도록 설계한다.

### 태블릿 / 폴드 펼침

- 가용 폭이 충분하면 왼쪽 목록 280~320px, 오른쪽 대화 나머지 공간. 펼친 폴드에서도 대화 영역 최소 360px를 확보할 수 없으면 1열 유지.
- 세로·가로·분할 화면 전환 시 선택한 방, 초안, 첨부, 스크롤 위치를 유지한다. 접었다 펼쳐도 새 대화처럼 초기화하지 않는다.
- 화면 높이는 고정 최대 높이 없이 가용 공간 전체 사용. 목록과 메시지만 각각 스크롤, 앱 전체가 중복 스크롤되지 않도록 한다.
- 목록 접기 버튼을 제공한다. 세로 화면에서 대화 집중 모드로 전환 가능.
- 태블릿에서도 휴대폰 UI를 단순 확대하지 않는다. 본문은 동일한 기본 크기를 유지하고 여백과 열 수로 공간을 활용한다.

### 데스크톱

- 좌측 탐색 레일 56~64px, 대화 목록 280~340px, 나머지 대화. 목록 너비는 드래그 조절하고 기기별 저장.
- 대화 목록 한 줄: 프로필, 이름, 오른쪽 시간; 두 번째 줄: 마지막 메시지, 오른쪽 안 읽은 수. 현재 여러 줄로 늘어진 정보 밀도를 줄인다.
- Enter 전송 / Shift+Enter 줄바꿈은 설정 가능한 기본값으로 제안한다. 한글 IME 조합 중 Enter는 전송하지 않는다.
- Ctrl+F 대화 검색, Esc 검색·팝업 닫기, Ctrl+V 이미지 붙여넣기, 드래그 앤 드롭 지원을 정돈한다. 브라우저 기본 동작과 충돌하는 단축키는 범위를 제한한다.
- 별도 대화창은 P2. 사용자가 누른 ‘새 창’에서 열고 팝업 차단 시 대체 경로를 제공한다. 웹에서 작업표시줄 그룹 분리·항상 위·창 위치 복원을 모든 환경에 보장하지 않는다.

## 3. 메시지 표시 상세

- 송신 말풍선은 오른쪽, 수신은 왼쪽. 시간은 말풍선 바깥 하단의 중앙 방향: 송신 왼쪽, 수신 오른쪽.
- 안 읽은 수는 시간 위에 작은 숫자. 현재 1:1은 상대 미확인 시 1, 읽으면 사라짐. 읽음 정보를 아직 받지 못한 상태를 ‘읽음’으로 단정하지 않는다.
- 그룹 채팅 시 숫자는 메시지별 수신 대상 중 미확인 인원으로 확장한다. 현재 1:1의 숫자를 그룹 인원으로 단순 대체하면 안 된다.
- 날짜 구분선, 연속된 같은 발신자의 묶음, 긴 URL/한글 파일명 줄바꿈을 추가한다. 본문 공백·줄바꿈은 보존한다.
- 기본 본문 14px 유지 후 사용자 조절(1% 단위)을 존중한다. 보조 시간은 10~11px보다 작아지지 않도록 향후 최소 가독성 검토. 글자만 커져도 버튼·말풍선이 잘리지 않게 한다.
- 사진은 이미지가 본문, 일반 파일은 이름·크기·만료일·저장 아이콘. 전송시각/읽음 수는 카드 바깥 공통 위치.
- 이미지 확대에서 원본 비율, 줌/이동, 저장/닫기, 포커스 복귀를 제공한다. 파일이 만료되면 대화와 파일명 및 ‘보관기간 만료’를 유지한다.
- 현재 ‘새 메시지 도착 시 항상 맨 아래’는 사용자가 요청한 동작이라 유지한다. 이후 선택 가능한 ‘이전 대화 읽는 중에는 새 메시지 버튼만 표시’ 모드를 제안하며 임의로 바꾸지 않는다.

## 4. 전송·읽음·알림 경험

- 상태는 준비→전송 중→전송 완료 또는 실패. 서버 저장 완료 전에는 읽음 숫자를 표시하지 않는다.
- 대용량은 전송량/전체량과 퍼센트 표시. 속도·남은 시간은 측정 가능할 때만 제공한다. 취소 시 임시 조각 정리와 재전송 정책도 함께 구현한다.
- 파일은 선택 직후 이름·크기·제한 확인. 여러 파일 지원 시 개별 진행/실패/취소를 제공하고 동시 업로드 수를 제한한다.
- 오프라인은 상단 작은 상태띠로 표시하고 입력 초안은 보존한다. 자동 복구와 수동 재전송이 동시에 발생해도 메시지 키로 중복을 막는다.
- 대화 알림 끄기(계정 설정)와 이 기기 푸시 켜기(기기 설정)를 명확히 나눈다. 권한 거부 시 재요청 반복 대신 브라우저 설정 안내.
- 읽음은 실제로 대화가 보이고 활성 상태일 때만 반영한다. 다른 기기에서 읽었을 때 실행 중 UI 동기화와 닫힌 기기의 홈 아이콘 알림 정리는 구분한다.
- 갤럭시 Chrome 홈 아이콘 숫자는 사용자의 실기 확인이 있으나 Edge 숫자 미표시 및 닫힌 기기의 읽음 정리는 미해결로 표기한다. 설치/알림 화면에서 지원을 과장하지 않는다. 이 문제의 추가 구현은 사용자 요청대로 보류.

## 5. 친구·검색·설정

- 친구 화면: 검색, 받은 요청 수, 친구 목록. 보낸 요청·차단 목록은 접힌 관리 영역. 검색/요청 제한 문구는 도움말에 넣되 제한에 걸리면 남은 대기 시간을 명확히 알린다.
- 친구 검색은 정확한 ID, 프로필 확인, 요청 버튼 순서. 요청 중/수락됨/거절 후 대기 상태를 버튼에 반영해 중복 요청 혼란을 줄인다.
- 대화 목록 검색과 대화 내용 검색을 분리한다. 결과는 검색어 강조·날짜·앞뒤 문맥·원문 이동·최근 대화로 복귀를 제공한다.
- 설정에는 프로필, 글자, 화면 모드, 테마, 기기 알림, 차단 관리, 로그아웃을 모은다. 설치 안내는 이미 설치된 상태에서 반복 노출을 줄인다.
- 향후 AI 참여는 이름 옆 AI 표식, 실행 중/완료/실패, 도구 실행 승인과 작업 결과 링크로 구분한다. 현재 사람 간 대화 UI를 먼저 안정화하고 dot/Codex/Gemini/Claude 연결은 별도 단계로 둔다.

## 6. 실행 순서와 검증

1. P0 화면 구조: 친구·대화·설정 분리, 상대 이름 노출, 헤더 정리, 높이·키보드·폴드 대응.
2. P1 읽기/작성: 목록 밀도, 날짜/메시지 묶음, 초안, 사진 확대, 파일 진행·취소, 검색 정리.
3. P2 생산성: 별도 창, 대화 고정·안 읽음 필터, 파일 서랍, 다중 파일. 메시지 수정·삭제 및 그룹/AI는 데이터 정책을 정한 뒤 진행.

검증 행렬: 360/390/412px 휴대폰 폭, 폴드4 접힘·펼침 실제 폭, 768/800/1024px 태블릿, 1280/1440/1920px 데스크톱. 각 조건에서 글자 100/125/150/200%, 긴 이름·URL·파일명, 다크 모드, 빈 목록, 안 읽음 99+, 키보드, 회전, 분할 화면을 확인한다.

필수 시나리오: 목록→대화→뒤로 위치 복원; 입력 중 방 전환/접기·펼치기 초안 유지; 300MB 업로드·실패·재시도 및 다운로드 해시 확인; 검색 중 새 메시지 도착; 두 계정 읽음 수 소멸; 차단/해제 후 이력 보존; 7일 전 안내와 만료 파일 표시.

합격 기준: 360px에서 가로 스크롤 0, 기본 크기에서 최근 대화가 첫 화면에 노출, 키보드로 입력칸 가림 0, 터치 주요 동작 44px 이상, 읽음/연결/전송 상태를 색만으로 구분하지 않음, 키보드 포커스와 화면 읽기 이름 제공. UI 개편은 기존 메시지·파일 경로·수신 권한을 바꾸지 않고 단계별 배포한다.
