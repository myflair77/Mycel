# 일반 그룹채팅·팀채팅 설계안

상태: 설계 제안. 팀채팅 선택·관리·전환은 아직 구현하지 않았다. 2026-11-15 적용한 기능은 1:1에서 별도 그룹 생성과 신규 참여자의 이전 기록 접근 제한이다.

## 생성과 사용자 안내

처음 3명 이상으로 시작하거나 1:1에서 사람을 추가할 때 참여자 선택 다음에 방 종류를 선택한다. 기본값은 일반 그룹채팅이다. 1:1 원본 방은 항상 유지하고 새 그룹에는 원본 대화·파일을 복사하지 않는다. 기존 그룹에 사람을 추가할 때는 현재 방 종류를 유지한다.

| 선택 카드 | 간단한 사용자 안내 |
| --- | --- |
| 일반 그룹채팅 | 친구들과 자유롭게 대화해요. 참여자가 친구를 초대하고 방 이름을 바꿀 수 있어요. |
| 팀채팅 | 방장이 참여자와 초대 권한을 관리해요. 업무나 모임을 운영할 때 적합해요. |

두 카드 아래 공통 안내: **새 참여자는 참여 이후의 대화와 파일만 볼 수 있어요.**
팀 선택 시: **방을 만드는 사람이 첫 방장이 됩니다.**
종류 변경 확인 시: **대화·파일은 유지됩니다. 이전 기록의 공개 범위는 바뀌지 않습니다.**
모바일에서는 세로 카드, 넓은 화면에서는 가로 카드. 자세히 보기에서 권한 표를 표시한다. 방장이나 과거 기록 정책이 설명 없이 바뀌지 않도록 최종 생성 화면에 종류·참여자·방장을 함께 표시한다.

## 권한

| 기능 | 일반 그룹채팅 | 팀채팅 |
| --- | --- | --- |
| 대화·답장·파일 | 모든 참여자 | 모든 참여자 |
| 친구 초대 | 모든 참여자 | 기본 방장·관리자, 방장이 허용하면 모든 참여자 |
| 방 이름 변경 | 모든 참여자 | 방장·관리자 |
| 공지 지정·해제 | 모든 참여자 | 방장·관리자 |
| 게시글 작성·본인 글 수정 | 모든 참여자 | 모든 참여자 |
| 참여자 내보내기 | 없음 | 방장·관리자. 관리자는 다른 관리자/방장 제외 |
| 관리자 지정·해제 | 없음 | 방장 |
| 방장 넘기기 | 없음 | 현 방장 제안 + 새 방장 수락 |
| 방 종류 변경 | 전원 동의 제안 | 전원 동의 제안 |

관리 권한은 다른 사람의 메시지 수정 권한을 포함하지 않는다. 본인 메시지 수정·삭제 정책은 유지한다. 관리 목적의 다른 사람 메시지 숨김은 별도 기능으로 설계하고 변경 기록을 남긴다. 팀 전환 시 기존 공지·게시글은 유지하되 이후 공지 변경부터 새 권한을 적용한다.

차단 관계가 있는 참여자의 초대는 기존 정책대로 거절한다. 일반/팀 구분은 차단 정책이나 파일 만료 정책을 변경하지 않는다. 팀채팅 과금은 이 설계의 전제 조건이 아니다.

## 일반 ↔ 팀 전환

방을 새로 만드는 방식과 별도로, 우리 메신저는 같은 방을 유지하는 전환을 제안한다. 방 ID·메시지 ID·첨부·개인 알림/읽음 위치·각 참여자의 과거 기록 접근 시작점은 그대로 유지한다.

1. 현재 참여자 누구나 더보기 → 방 종류 변경 제안을 만든다. 동시에 열린 제안은 한 개만 허용한다.
2. 일반→팀은 방장 후보(현재 참여자)와 초대 권한을 함께 제시한다. 팀→일반은 방장/관리자 권한과 내보내기 권한이 없어짐을 알린다.
3. 제안 당시의 활성 인간 참여자 전원이 72시간 안에 동의해야 한다. 제안자도 변경 내용을 확인하고 동의한다. 방장 후보 수락은 별도 명시한다. 미응답은 동의가 아니다.
4. 한 명이라도 거절하거나 제안자가 취소하거나 기한이 지나면 종료하고 기존 상태를 유지한다. 누구의 반대인지 전체 공개하지 않고 동의 인원/종료 사유만 표시한다.
5. 대화는 투표 중에도 계속된다. 새 참여/퇴장/탈퇴가 발생하면 명단이 달라졌다는 안내와 함께 제안을 무효화한다. 현재 명단으로 다시 제안할 수 있다.
6. 투표 중 관리자 내보내기·역할 변경은 잠시 막아 반대자를 제거해서 통과시키지 못하게 한다. 자발적 나가기는 허용하며 제안을 무효화한다. 권한 정책 변경도 제안을 무효화한다.
7. 서버가 방을 잠근 뒤 명단/권한 버전, 기한, 동의, 방장 수락을 재확인하고 한 번만 전환한다. 중복 클릭·재연결은 같은 제안 ID로 멱등 처리한다.
8. 전환 완료 시스템 안내를 남기고 모든 기기의 메뉴 권한을 갱신한다. 팀→일반이면 관리 역할을 비활성화하며 이전 역할은 감사 기록으로만 보존한다.

거절 후 재제안은 24시간 뒤, 방당 하루 3회 이하로 제한하는 것을 제안한다. 긴급히 별도 운영이 필요하면 새 방을 만들고 자발적으로 참여하도록 초대한다. 이전 대화를 자동 복사하지 않는다.

## 과거 대화·파일 보호

방 종류 변경은 참여 시점 제한을 완화하지 않는다. 팀으로 바뀌어도 늦게 들어온 사람이 이전 기록을 보지 못한다. 다시 나갔다 들어오면 재참여 시점을 새 기준으로 삼는다. 기존 계속 참여자는 원래 보던 기록을 유지한다.

이전 기록 일괄 공개는 초기 팀채팅 범위에서 제외한다. 향후 추가한다면 현재 참여자만의 표결로 퇴장한 작성자의 내용을 공개하지 않는다. 원 작성자/권리자의 동의와 범위를 별도로 설계해야 한다. 현재처럼 접근 가능한 메시지를 명시적으로 전달하면 그 전달 메시지는 새 기록으로서 새 참여자에게 보인다.

검색, 파일 목록·다운로드, 답장 원문, 게시판·공지, 중요 표시, 최근 대화 미리보기에 동일한 서버 권한을 적용한다. 이미 사용자가 내려받은 파일이나 외부에 복사한 내용까지 회수하지는 못한다. 새 파일 30일 보관·만료 7일 전 안내·원본 삭제 후 파일명 유지 정책은 방 종류와 무관하다.

## 방장 나가기·인원 감소

방장은 다른 현재 참여자에게 방장을 넘기고 상대가 수락한 뒤 나갈 수 있다. 수락 전에는 기존 방장이 유지된다. 방장만 남은 경우 확인 후 나가고 방은 비활성 상태로 남긴다. 나가기를 전체 대화·원본 삭제와 연결하지 않는다. 강제 계정 삭제나 방장 장기 부재의 자동 승계는 초기 범위에서 제외하고 별도 복구 절차를 마련한다.

그룹 인원이 2명이나 1명으로 줄어도 자동으로 1:1/나와의 대화로 바꾸지 않는다. 방 종류와 기록이 유지된다.

## 데이터·서버 구현 제안

- 기존 direct/self/group 구조 유지. 그룹에 group_mode(regular/team), owner_id, invite_policy, membership_version, policy_version 추가.
- 구성원 role(member/admin/owner), 기존 visible_after_sequence와 joined_sequence는 유지.
- room_mode_proposals: 제안 ID, 이전/목표 종류, 방장 후보, 정책, 명단/권한 버전, 상태, 만료 시각.
- room_mode_votes: 제안+회원 고유 키, 동의/거절, 서버 시각. 본인만 투표 가능.
- room_events: 전환/역할/초대/퇴장 기록. 일반 참가자에게 필요한 사건만 노출하고 민감한 투표 상세는 제한.
- 모든 권한 검사와 전환은 DB RPC에서 수행한다. 화면에서 버튼을 숨기는 것만으로 제한하지 않는다.
- 향후 AI 참여자는 별도 서비스 신원으로 관리하며 투표권/방장 권한을 자동 부여하지 않는다. AI에도 같은 과거 기록 범위를 적용한다.

## 구현·검증 순서

1. 일반/팀 생성 카드와 안내, 서버 역할·권한, 기존 그룹을 regular로 유지하는 마이그레이션.
2. 방장 위임·관리자·초대 정책·참여자 관리.
3. 동의 기반 양방향 전환과 감사 기록.
4. 3개 이상 계정으로 새 참여자 이전 기록 차단, 현재 참여자 기록 보존, 거절/만료/회원 변경/중복 전환/오프라인 복귀를 검증.
5. 실제 노트북·접힌 폴드·펼친 폴드에서 선택 설명, 권한 메뉴, 전환 알림 확인.
